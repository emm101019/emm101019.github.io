Software Design and Engineering

My Weight Tracker Android app began as a CS 360 project in February 2026. The original app allowed users to create an account, log in, and open a home screen. It had database methods for weight records, but the home screen and buttons were not fully connected to them.

Software Design and Engineering Narrative

I selected this app because it shows how my software design skills have improved. I reorganized the project into smaller parts, including a WeightEntry model, separate repositories, shared validation rules, and a progress calculator. This made the code easier to read, test, and update.

I added working screens to create, view, edit, and delete weight entries. The home screen now displays the current weight, goal weight, and progress. I connected navigation buttons and added clear messages when information is missing or cannot be saved.

I also improved security and reliability. New passwords are stored as salted PBKDF2 hashes, and older accounts are upgraded after a successful login. I removed an unused permission, disabled app-data backup, and blocked cleartext network traffic. I added labels, content descriptions, delete confirmation, and unit tests.

These changes show my progress toward course outcomes two, three, four, and five through communication, computing solutions, software development, and security. Collaboration is less directly represented because this was an individual project, but clearer organization and documentation help another developer understand the work.

The biggest challenge was turning a screen that looked finished into a feature that worked. I learned that separating the model, repositories, validation, and user interface makes changes easier to manage. I also had to consider existing accounts when changing password storage. The enhanced app is more complete and easier to maintain.

Algorithms and Data Structures

My Weight Tracker Android app began as a CS 360 project in February 2026. For this enhancement, I added a way to sort and analyze weight entries so users can better understand their progress over time.

Algorithms and Data Structures Narrative

The app loads weight entries into an ArrayList and sorts a copy by date, from oldest to newest. A comparator uses the entry ID to determine the order when dates match. Sorting a copy keeps the original database results unchanged.

The analyzer uses a seven-entry sliding window and a running sum to calculate a moving average. It also calculates total weight change, progress toward a goal, and a streak of entries moving closer to the goal. The dashboard displays a summary and trend chart. Invalid dates and weights are skipped, and the user is notified.

Sorting takes O(n log n) time and the calculations take O(n). Tests cover empty and one-entry histories, unsorted and duplicate dates, invalid data, goal progress, improvement streaks, and larger histories.

This enhancement demonstrates how I use algorithms and data structures to solve a problem and apply Android development tools to create a useful feature. The database returns entries newest first, so sorting the copy for the chart was an important design decision. I learned how sorting, a sliding window, and testing edge cases can make weight history easier to understand.

Databases

My Weight Tracker Android app began as a CS 360 project in February 2026. The original version used SQLite to store accounts and weight records. For this enhancement, I improved how the app stores and organizes that information.

Database Enhancement Narrative

I moved the enhanced app from SQLite helper methods to Room. I added account and weight-entry entities, data access objects, and a repository. Each new weight entry is connected to the signed-in account. I also added an index to support account and date searches.

The migration preserves account information and valid weight history from the older database. I added a database test for saving, reading, changing, and deleting entries, as well as keeping entries separated by account.

This enhancement shows my progress toward course outcomes three, four, and five. It demonstrates database design, the use of Room and testing tools, and attention to safer data handling through account links and password hashing.

I learned that changing a database involves more than creating new tables. I needed to preserve older information and connect each record to the correct account. Planning the migration without erasing saved history was the biggest challenge. This work made the database easier to maintain and the saved data more organized.
